# Commands

What each of the repository's commands builds, checks and writes, and how CI runs it. `CLAUDE.md` has the short list, with when to run each. Run them from the repo root (pnpm 12).

- `pnpm dev`: start the desktop app with hot reload.
- `pnpm check`: the static checks and unit tests CI runs (`lint`, `typecheck`, `deps`, `knip`, `licence-check`, `ui-strings`, `help-check`, `react-compiler`, `test`, `test:compiled`). Run it before opening a PR.
- `pnpm e2e`: builds the desktop app and runs the Playwright tests: the Electron app (`e2e/app/`) and the exported fixture site opened from disk in Chromium, Firefox and WebKit (`e2e/export/`). Also run in CI on Linux, Windows and macOS for every ready PR, with Firefox and WebKit only when the exported site can change. On this machine run only the specs a change touches (`pnpm e2e app/<name>.spec.ts`, with no `--`), when touching main, preload, the renderer bootstrap, security settings, site components or the pipeline; all of it only to chase a failure CI found. First time: `pnpm --filter @webforge/e2e exec playwright install chromium firefox webkit`.
- `pnpm e2e:packaged`: packages the app (`electron-builder --dir`) and runs `e2e/packaged/` against it (CI on Windows + macOS for every ready PR). Run it when touching packaging, Fuses or native modules.
- `pnpm visual`: builds the editor UI's and the site components' Storybooks and runs `e2e/visual/` (screenshots only in CI's Linux container). Run it when touching `packages/editor-ui`, `packages/site-components` or `packages/templates`.
  - The editor UI: axe on every story, in dark and light.
  - The site components: axe on every story, plus a keyboard check, on Desktop and Mobile in the three development presets. `VISUAL_ALL_THEMES=1` checks every preset, as the nightly run does.
  - Every page of every template: axe and screenshots on Desktop and Mobile.
- `pnpm visual:docker`: the same with screenshots, in CI's pinned Playwright container on this machine (Docker Desktop must be running). It copies the working tree as git sees it, writes screenshots for new stories, and with `--update` also rewrites changed ones (review them with `git diff` first); `pnpm visual:docker -- --grep Picker` runs a subset. Run it before marking a PR ready whenever stories were added or changed, and commit the screenshots with the PR, so CI doesn't fail on them and need a second run. `pnpm --filter @webforge/editor-ui storybook` (or `@webforge/site-components`) opens Storybook.
- `pnpm template-thumbnails`: rewrites each template's `thumbnail.png` (its home page as the export draws it, at 1280×800) in the same container, through `visual:docker`. Run it after adding a template or changing one, or anything its home page is drawn with, and commit the result: CI's Storybook job checks they're current.
- `pnpm bench`: the benchmarks of the history, autosave's commit, the export, the preview's builds and Site Check (`bench/`, ADR 0022), each written to `bench/results/`. CI's Benchmarks job runs `main` and the PR in two interleaved rounds and fails one more than 20% slower in both (`node tools/src/compare-bench.ts --base <dirs> --head <dirs>` compares the same way locally). Run it when touching those packages' hot paths.
- `pnpm e2e:perf`: builds the app in perf mode and runs its timings against architecture §10's budgets (`e2e/perf/`, ADR 0007): editing a large page, the commit, opening a site, the preview and a 20-page export. CI's Performance job runs it nightly on Windows and macOS, then builds the installers and checks their size (`tools/src/check-installer-size.ts`); never on a pull request. Run it before and after performance work and when upgrading Puck.
- `pnpm format`: apply Biome fixes. `pnpm build`: build all workspaces.
- `pnpm scaffold area|panel|commands|field-kind|ipc-domain <Name>` and `pnpm new-component <Name> --place section|element|child --help-page <page> [--category <group>]`: write a new part of the editor, or a site component, with its strings, story and test, and register it (`docs/extending.md`, `docs/components.md`).
- `pnpm behaviours`, `pnpm font-catalogue` and `pnpm catalogue-data`: regenerate `packages/site-components/src/behaviours/index.ts` (a site-components test fails when it is stale), `packages/themes/src/fonts/catalogue.json` (the bundled family list is in `tools/src/build-font-catalogue.ts`) and `packages/site-components/src/catalogue-data.json` (the catalogue as data for AI apps; a test fails when it is stale). Run them after adding or renaming a behaviour file, editing that list, or changing a component's fields or defaults, and commit the result.
- `pnpm main-strings`: regenerates `packages/i18n/src/en/main.ts`, main's own catalogue (ADR 0027), from the keys main's and the shared code's files name. Run it after adding or changing a string main shows, and commit the result: a test fails when it is stale.
- `pnpm app-icons`: redraws the desktop app's icons (`apps/desktop/build`) from the logo's masters in `apps/desktop/branding` (`tools/src/build-app-icons.ts`). Run it after changing a master and commit the result: a test fails when the icons are older than their masters.
